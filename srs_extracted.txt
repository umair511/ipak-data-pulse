--## 1. Executive Summary
IPAK Data Pulse is a **multi-plant enterprise production management platform** built
for a flexible-film manufacturing group operating four facilities: **IPAK, CPAK, GPAK
, and PETPAK**. The system captures real-time machine-level production, waste, downti

me, settings, cycles, dispatch, export and packing-cost data; defines shift-wise prod
uction targets; and presents consolidated KPI dashboards, deep analytics, and granula
r reports — all served from a **Node.js + PostgreSQL backend** with a **premium, Stri
pe/Apple-inspired UI** on Flutter (Web/iOS/Android) or React.
**Key Characteristics:**
- **Multi-plant, single-tenant** — User selects an active plant on login; all data en
try, dashboards, analytics, and reports are scoped to that plant (Packing Cost is the
only all-plants module).
- **Role-based access** — Four roles (Admin, Supervisor, Manager, Operator) gate ever
y navigation item and CRUD action.
- **Per-plant theming** — Each plant carries its own accent color, light/dark shades,
and gradient, applied consistently across the sidebar, top bar, buttons, chips, chart
s, and KPI cards.
- **Premium analytics** — ECharts-based charting with diverse visualizations: donut,
gauge, radial, treemap, sunburst, heatmap, stacked area, grouped bars, scatter plots,
and histograms.
- **Bulk import** — CSV/Excel import modal validates and persists Production Entries
and Film Codes via backend APIs.
- **Dispatch intelligence** — Dedicated Dispatch entity with entry and report pages b
reaking down Export vs Local shipments by customer and date.
--## 2. Project Overview
IPAK Data Pulse is a **Flutter (Web/iOS/Android)** application served by a **Node.js
+ PostgreSQL** backend. The frontend uses **Flutter** for a premium, smooth UI with a
nimations and native performance. The backend uses **Express.js** for REST APIs, **Pr
isma** as ORM, **PostgreSQL** as database, **JWT + Refresh Tokens** for authenticatio
n, and **Multer** for file uploads.
**User Experience Flow:**
1. **Login** — Email + Password (JWT access + refresh tokens issued).
2. **Plant Selection** — Choose IPAK / CPAK / GPAK / PETPAK; stored in device local s
torage.

3. **Layout Shell** — Premium collapsible sidebar (desktop) / bottom navigation (mobi
le), top bar showing active plant badge, current date, and user avatar.
4. **Module Pages** — Dashboard, Production Entry, Targets, Reports, Analytics, Expor
t Quantity, Packing Cost, Dispatch, Dispatch Report, Masters, User Management, Permis
sions, Audit Logs.
--## 3. Purpose
To provide plant management, supervisors, and operators a single, real-time, consiste
nt source of truth for production performance across all four manufacturing facilitie
s — replacing manual spreadsheets and siloed records with a centralized, auditable, a
nalytics-driven platform.
--## 4. Objectives
- Record per-shift production, waste, downtime, settings, and cycles for every machin
e in every section of every plant.
- Define and track shift-wise production targets for Slitter machines.
- Capture dispatch (export and local) quantities and break them down by customer and
date.
- Track export shipment quantities and monthly packing costs across all plants.
- Deliver instant KPI summaries (This Month and Yesterday) per section and per dispat
ch type.
- Deliver deep, machine-level and section-level analytics.
- Enforce role-based access and plant-scoped data isolation.
- Allow admin-controlled user creation with role, plant, section, and module access a
ssignment.
- Provide bulk data import for high-volume historical data.

--## 11. Every Screen
### 11.1 Login (`/login`)
- **Purpose:** Authenticate user.
- **Fields:** Email (text), Password (text, toggleable show/hide).
- **Buttons:** Sign In (submit, disabled while empty/loading), password show/hide tog
gle, "Forgot Password?" link.
- **Validations:** Both fields required; email format validation.
- **Business Logic:** On submit, frontend calls `POST /api/auth/login`. Backend valid
ates credentials via Prisma, compares bcrypt hash, issues JWT access + refresh tokens
stored in HttpOnly cookies. On success, navigates to `/select-plant` or `/dashboard`.
On failure, shows "Invalid email or password.".
- **UI:** Glassmorphism card centered on screen, Apple-style inputs with floating lab
els, haptic feedback on mobile.
### 11.2 Plant Selection (`/select-plant`)
- **Purpose:** Choose active plant.
- **Fields:** Four plant cards (IPAK, CPAK, GPAK, PETPAK) with gradients and icons.
- **Buttons:** Each plant card; "Sign out".
- **Validations:** None.
- **Business Logic:** Selecting a plant calls `switchPlant({id, name})` (writes local
Storage/shared_preferences) then navigates to `/dashboard`. Sign out clears tokens an
d navigates to `/login`.

- **UI:** Premium cards with glass effect, smooth hover/scale animations, plant logos
with gradient overlays.
### 11.3 Dashboard (`/dashboard`)
- **Purpose:** Instant KPI overview per section and dispatch, deep-linking into repor
ts.
- **Fields:** None (read-only).
- **Buttons / Cards:** `KPICard` (clickable) × 4 sections × 2 rows (This Month, Yeste
rday), plus a Dispatch dashboard with 3 cards × 2 rows.
- **Validations:** None.
- **Business Logic:** Fetches `GET /api/dashboard/kpis?plant={plant}`. For each secti
on ('Film Line', 'Slitter', 'Metallizer'), computes This Month (1st-of-month → today)
and Yesterday metrics: production tons, waste tons, waste %, downtime minutes → hours
, settings (Slitter) or cycles (Metallizer). Dispatch dashboard computes This Month a
nd Yesterday totals, plus Export and Local splits. Each card navigates to `/reports?r
eportType=...&section=...&dateFrom=...&dateTo=...` (production) or `/dispatch-report?
view=report&dateFrom=...&dateTo=...&dispatchType=...` (dispatch).
- **UI:** Glassmorphism cards with subtle gradient borders; clickable cards with ripp
le effect. KPI values in large, bold typography.
### 11.4 Production Entry (`/production`)
- **Purpose:** Create/edit/delete per-shift production records; bulk import.
- **Fields (form):** Date (date picker), Shift (Morning/Evening/Night chip buttons),
Machine (chip grid), Film Code (searchable dropdown), Production (Tons numeric input)
, Waste (Tons numeric input), Waste % (auto-calculated read-only), Downtime (Minutes
numeric), Downtime Reason (dropdown conditional), Number of Settings (Slitter only),
Number of Cycles (Metallizer only).
- **Buttons:** "Add Entry", "Bulk Import", per-row Edit/Delete, Save/Cancel.
- **Validations:** Date required, Shift required, Machine required, Film Code require
d, Production ≥ 0, Waste ≥ 0, Downtime Reason required when downtime > 0, Settings re
quired (≥ 0) for Slitter.
- **Business Logic:** Machine selection auto-sets section. Film code dropdown filters
by name. On save, builds payload with plant_id/plant_name, parsed numbers, auto waste
_percent, conditional settings/cycles, `created_by_name`. Calls `POST /api/production
`. Edit re-opens the form prefilled.
- **Calculations:** `wastePercent = (wasteTons / productionTons) * 100` (2 dp) — comp
uted on backend before save.
- **UI:** Premium form with floating labels, chip selectors, animated transitions. Bu
lk Import modal with file dropzone.

--## 12. Complete Dashboard Documentation
The Dashboard (`/dashboard`) is composed of three helper components: `KPICard`, `Sect
ionDashboard`, `DispatchDashboard`.

**Date range helpers:**
- `buildMonthRange()` → `{dateFrom: YYYY-MM-01, dateTo: today}`
- `buildYesterdayRange()` → `{dateFrom: yesterday, dateTo: yesterday}`
**KPICard:** A clickable button-card. Props: `title`, `value`, `unit`, `subtitle`, `c
olor`, `icon`, `onClick`. Renders an icon tile (`color + '20'` background), the value
with unit, and subtitle. Hover lifts the card and shows a ring in the accent color.
**SectionDashboard (per section):** For each of Film Line / Slitter / Metallizer:
- **This Month row:** Production (T, theme color, → Overall Production report), Waste
(%, amber, → Waste report), Downtime (hrs, red, → Downtime report), plus Settings (Sl
itter, purple) or Cycles (Metallizer, purple).
- **Yesterday row:** Identical metrics scoped to yesterday.
**DispatchDashboard:**
- **This Month:** Total Dispatch (theme), Export Dispatch (sky), Local Dispatch (gree
n).
- **Yesterday:** Identical three cards scoped to yesterday.
**Data Load:** `Promise.all([fetch('/api/dashboard/kpis?plant=...'), fetch('/api/dash
board/dispatch?plant=...')])`.

38. Complete Business Rules
#
BR01
BR02
BR03
BR04
BR05

Rule
A production entry's section is derived from the selected machine.

Waste % is always waste/production * 100; it is stored on the record and recomputed in reports.

Downtime reason is mandatory iff downtime_minutes > 0.

number_of_settings is captured only for Slitter and is required (≥ 0).

number_of_cycles is captured only for Metallizer (optional).

#
BR06
BR07
BR08
BR09
BR10

Rule
Targets are Slitter-only and shift-wise.

Achievement % uses actual production for the same date + machine + shift.

Dispatch type is Export or Local; customer name is optional.

Packing cost per-ton = total cost / total production; group total re-divides sums.

Only Active film codes and downtime reasons appear in production entry selects.
