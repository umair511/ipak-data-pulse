## 3. SCHEMA COMPARISON

### 3.1 Models: Hono vs NestJS

| Hono Model | NestJS Equivalent | Status |
|------------|-------------------|--------|
| User | User | ⚠️ Different fields |
| Machine | Machine | ⚠️ Different fields |
| FilmCode | Product | ⚠️ Renamed, different fields |
| DowntimeReason | ❌ Missing | 🔴 Need to add |
| ProductionEntry | ProductionEntry | ⚠️ Different fields |
| Target | Target | ⚠️ Different fields |
| ExportQuantity | ❌ Missing | 🔴 Need to add |
| PackingCost | Packing | ⚠️ Completely different |
| Customer | Customer | ⚠️ Different fields |
| Dispatch | Dispatch | ⚠️ Different fields |
| AuditLog | AuditLog | ⚠️ Different fields |
| UserPermission | JSON field on User | ⚠️ Different approach |
| UserPlant | Single `plant` field | ⚠️ Different approach |
| — | RefreshToken | ✅ NestJS-only (good) |

### 3.2 Key Schema Differences

**Hono uses denormalized strings:** `plantName`, `filmCodeName`, `machineName` stored directly on records
**NestJS uses references:** Relies on relations and joins

**Decision: Use Hono's schema as base** — it matches the React frontend perfectly. Add PostgreSQL improvements (proper types, indexes, `deletedAt` for soft delete).

### 4.3 Auth Upgrade

| Feature | Hono (Current) | NestJS (Target) |
|---------|----------------|-----------------|
| Login | Username + SHA-256 | Email + bcrypt |
| Token | None (stateless) | JWT (15min access + 7d refresh) |
| Password | SHA-256 hash:salt | bcrypt (12 rounds) |
| Session | None | Refresh token DB tracking |
| Guards | None | JwtAuthGuard on all routes |

**Migration:** Support both `username` and `email` for login during transition.

## 8. RISK MITIGATION

| Risk | Mitigation |
|------|------------|
| Frontend breaks on API change | Keep same URL patterns where possible; use query params same as Hono |
| Data loss during migration | Export SQLite data → transform → import to PostgreSQL |
| Auth incompatibility | Support username+email login; migrate passwords to bcrypt |
| Schema differences | Use Hono schema as base; add PostgreSQL features incrementally |
| Flutter depends on API | Document all endpoints; Flutter uses same API contract |
